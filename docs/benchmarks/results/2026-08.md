### Findings — both directions

- **The void floor held.** 0/4 correct with no code access (2 partial, 2 wrong); no flowtrace ticket
  was guessable from model priors alone. The correct-band floor is real.
- **No flowtrace correctness advantage over the baseline.** Both models solved all four tickets with
  and without the tool; the pre-registered >=1-ticket correctness margin was not met. On this run the
  tool's case cannot rest on correctness.
- **And no token advantage either.** The `.ft` arm spent slightly *more* than `.base` on the median
  and on most paired cells — so this single run gives the tool no cost win to fall back on. Stated
  plainly: flowtrace did not demonstrably help on either axis here.
- **The gap that cuts the other way.** The Sonnet predictions were set at 3/4 and both Sonnet arms
  returned 4/4 — the benchmark under-predicted the baseline as much as it under-predicted the tool.
- **All flowtrace cells scored.** The safeguard attrition that censored part of the wider run touched
  no flowtrace ticket; every verdict above rests on a real deliverable, not a survivor of attrition.

One run, four tickets, one corpus, strong-effort settings. These findings describe that and nothing
wider; the 5-run protocol is what would turn any of them into a claim.
